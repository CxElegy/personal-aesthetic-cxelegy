# 复刻方法：证据优先 + 完成循环 + 自我学习

参考并改编自两个 MIT 项目的思路（只借方法，不含其代码）：
- [morluto/rea](https://github.com/morluto/rea)（REA，Reverse Engineer Anything）：证据优先，每个结论都附证据和局限，明确列出未知项。
- [Speedrunlab/reverse-engineer-anything-self-learning-loop](https://github.com/Speedrunlab/reverse-engineer-anything-self-learning-loop)：动手前先写下「100% 是什么」，循环到每个必须项连续两轮通过；每一轮把学到的东西存下来。

**边界**：复刻的是「行为和设计思路」，不搬运原作的受保护内容（图片、插画、视频、代码、字体、商标）。原作的素材只用来对比，不放进复刻里；需要类似的素材时自己画，或者用 AI 重新生成。

## 第 1 步：检查原作（先找源头，再看视频）
- **原作能直接打开吗？** 公开网站（例如 blossom-carousel.com、reactbits.dev、作者的作品集）→ 用 Playwright 打开，记录 DOM 结构、用到的库（看脚本文件名、全局变量）、动画参数（CSS transition、keyframes、requestAnimationFrame 的写法）、网络请求（模型、Lottie / Rive 文件）。这比看视频猜准确得多。
- 只有视频 → 抽帧（关键瞬间每秒 8 帧以上，再放大局部），数一数姿势和状态，量一量时长和节奏。
- 每条发现写进 `catalog/items.json` 条目的 `evidence`，并标明信心：
  - **observed（观察到）**：页面代码里读到，或者逐帧看到的。
  - **derived（推导）**：两个以上独立线索指向同一个结论。
  - **inferred（推测）**：只有一个线索，或者只是「像」。推测不能当作已知事实来定方案。
- 不知道的写进 `unknowns`，并写明要怎样才能知道。

## 第 2 步：动手前写清单（定义 100%）
用 `templates/parity-checklist.md`。每一项写：区域、行为、「操作 → 应该看到什么」、怎么验证、**通过的标准（动手前写，之后不准改松）**、档位（必须 / 应该 / 不做）。
- 原作里用户点名喜欢的那个瞬间，必须是「必须」项。
- 「不做」的项也写出来，免得以后反复讨论。

## 第 3 步：做
先判断原作的**技术层级**（矢量补间 / 骨骼加网格变形 / 逐帧 / 3D / 实拍 / 视频），选同一层级或者能达到同样效果的做法。层级低一级，就封顶在 RUBRIC 的上限；动手前就要告诉用户这个上限。

## 第 4 步：对比和差距报告
- `node tools/verify/compare.js <id>` 生成逐帧对比；关键瞬间另外放大对比。
- 按清单逐项判断通过或失败，附证据（截图路径）。用 `templates/gap-report.md` 写：**先列退步**（上一轮通过、这一轮失败的），再按严重程度列失败的必须项（不能用 / 结果不对 / 只是外观），再列无法测试的项。
- **独立复查**：开一个没看过我结论的审查员（子代理），只给它原作帧、复刻帧和清单，让它独立判定并补充「原作有、清单没写到」的行为。两边结论不一致的项按失败处理。
- 按 `tools/verify/RUBRIC.md` 打分。

## 第 5 步：循环
按差距报告「下一轮先打哪一项」改，再回到第 4 步。完成 = 所有必须项连续两轮通过，并且用户接受剩下的差距。用户打分后，按 RUBRIC 的校准规则调整标准。

## 第 6 步：自我学习
每一轮结束，把**对以后的复刻也成立**的经验写进 `LESSONS.md`（按主题归类，写成「规则 + 一句原因」，不要写成事件记录；同一条规则只加强，不重复追加）。只出现在一个作品上的特例不算经验。
